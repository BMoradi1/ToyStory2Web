 HOW TO USE THIS FILE
   Work top to bottom. Phases are ordered by dependency, not by appeal.
   Anything marked [BLOCKED] names what it waits on. Update status markers as
   you go and keep docs/FORMATS.md in sync when a format is cracked.

 STATUS
   [DONE]      finished and verified
   [ACTIVE]    in progress right now
   [READY]     unblocked, nobody on it
   [BLOCKED]   waiting on a named dependency
   [OPEN]      not yet understood; research needed

 THE THREE RULES (see CLAUDE.md)
   1. No game assets in git, ever. Users supply their own copy.
   2. "Toy Story 2/" is read-only. It is the user's only copy.
   3. Never call a format solved without parsing it end to end and validating.

 PHASE 1 - ASSET PIPELINE
================================================================================
 [DONE]   .ngn textures - 24bpp BMPs, browser-decodable, sparse slot IDs
 [DONE]   .ALL container parser  (src/formats/all.ts; verified 88/88 files)
          - u32@0 = metadata offset in 16-BIT WORDS (x2 for bytes)
          - metadata: u32 count N, then N x 0x4C entries, ending exactly at EOF
          - types: 0x0001 mesh | 0x0006 collision | 0x0008 dyn collision
                   0x0009 target pos | 0x0101 infinite wall | 0x011F joint
 [DONE]   .ALL gfx mesh reader - 9556 faces across 694 groups, each group
          consuming exactly its declared size; renders as recognisable models
          !! CORRECTION: TS2 PC triangles store 3 VERTICES, not 4. The PSX-
          derived spec is wrong for this build. Face = 4 + n*8 + (n-1)*4.
 [DONE]   .ALL gfx joint reader - 433 joints, magic 0x12345678
 [READY]  .ALL collision reader - 44-byte polys (22 x i16), p2/p3/p4 as deltas
          from origin; bouncing2 == 0x7FFF means triangle, else quad
          (container confirmed; payload not yet parsed)
 [READY]  .ANM parser - magic 0xFFF0 (TS2 final). 10 bytes/bone/frame:
          i16 x/4,y/4,z/4 then a 20-bit packed rotation across two u16
          (rz = rot & 0x3FF, ry = (rot>>10) & 0x3FF, rx = (rot>>20) & 0x3FF,
          each x PI/512). Bones map 1:1 onto mesh groups by index. 20 fps.
 [READY]  .raw / .raws decoder - chunked RNC PRO-PACK, magic stripped,
          TS2 chunk size 0x830C. Same container for both extensions.
 [ACTIVE] PC .dat scene format  (agent working; genuinely undocumented)
          NOTE: the PC .dat is NOT the PSX .dat. The conversion rewrote it.
 [OPEN]   .vis / .kp2 / .kep / .new - no public documentation anywhere.
          Lead: .dat/.vis/.kp2 may share an 8-byte header + int32 XYZ triples.
          Do NOT assume .vis is a visibility set; content looks like paths.
 [READY]  Cutscene playback - rtlibs/*.dll are MPEG-1 system streams (214 MB).
          Needs an in-browser MPEG-1 decoder or a local transcode step.
 [READY]  Audio - 267 standard .wav files, no decoding work expected
 [READY]  creatures.cfg parser - plaintext entity table, id -> name -> dir

================================================================================
 PHASE 6 - MIPS INTERPRETATION (optional, for fidelity)
================================================================================
 Only worth doing where hand-reimplementation visibly falls short - boss
 timings, scripted set pieces. Not for basic movement.

 FEASIBILITY IS GOOD: level 1's overlay makes 109 calls to just 41 distinct
 functions. All 21 overlays total only 178 KB. These are per-level logic
 modules sitting on the engine, not the engine itself.

 [OPEN] MIPS R3000 interpreter (~60 instructions, no FPU; the GTE only matters
        for code being replaced by WebGL anyway)
 [OPEN] Identify and implement the engine import surface (est. 100-300 fns
        across all levels). Reference implementation is on disk: the called
        addresses fall inside psx.exe's .text (0x80010000 + 0x77000).
 [OPEN] BIG SHORTCUT: PeriBluGaming/ToyStory2Recomp ships seeds/functions.txt
        with 658 Ghidra-derived function entry points into the PSX executable.
        That directly attacks the "every import is an unnamed address" problem.
 [OPEN] Overlay loader and relocation

================================================================================
 KEY UNKNOWNS - the things most likely to derail the plan
================================================================================
 1. WHERE IS LEVEL VISUAL GEOMETRY? Not in .ALL (collision only). Either the
    PC .dat or inside .ngn beyond the textures. Nothing renders until this is
    answered. HIGHEST PRIORITY.
 2. Does the .ANM spec, written from PSX files, hold on this PC build? The
    .ALL container and mesh reader do (88/88 files) but only AFTER correcting
    the triangle vertex count, so expect .ANM to need similar correction.
 3. .vis / .kp2 / .kep / .new are undocumented publicly. We are first.
 4. How faithful can gameplay get without interpreting the original logic?
